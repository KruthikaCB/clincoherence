# Milestone 4A deterministic consistency foundation

Backend-only service and evaluator. No endpoint, frontend change, migration, audit persistence, model change, external call or PASS/WARN/CLARIFY/REFUSE assignment. Approved requirements and architecture are unchanged. All development fixtures are synthetic.

## Input and result contract

`evaluate_consistency(patient_id, current, history)` takes typed `FactVersion` values. History must contain all accepted versions, including current versions. The adapter obtains this complete history with a patient-scoped CONFIRMED query and current selection with existing `current_query`. Typed inputs reuse the existing fact vocabulary, units, provenance and timezone-aware timestamps. Non-synthetic/de-identified provenance fails schema validation.

Mixed-patient inputs raise a fixed error before any snapshot or findings. Foreign/missing parent identifiers are never echoed. PENDING/REJECTED input is reported as an accepted-membership integrity failure; all further evaluation short-circuits. Proposals are not loaded by the service and never become accepted state through evaluation.

Results contain a ruleset version, sorted current/history version IDs, sorted/deduplicated findings, checks run and explicit reasons for inapplicable checks. Findings contain only local version IDs and fixed rule/category/reason codes, never clinical values or source quotes. `evaluated_at` is generated by the service in a separate `ConsistencyRun` envelope; it is not part of deterministic evaluation content. Version IDs identify the immutable input snapshot; this is not a persisted aggregate state revision.

## Rules: longitudinal-structural-v1

- `membership`: all input statuses must be CONFIRMED; nothing else is evaluated if not.
- `current_selection`: exactly one current row per accepted chain, identical to the highest accepted version in history. Missing history/current rows, superseded selection and inconsistent copies are integrity findings.
- `chain`: valid root identity; unique version IDs/numbers; accepted parent exists in the same fact/category; parent number matches and precedes child; parent is the immediately preceding accepted version. Version numbers need not be consecutive. A skipped number due to a pending/rejected version is valid. Historical versions are not independently compared as current facts.
- `attribution`: author role matches patient-reported/practitioner-managed category. A chain cannot switch categories. Practitioner author changes within the category are not prohibited by this checker.
- `provenance`: correction reason is nonempty; structured facts have no fabricated confirmation markers; extracted accepted facts identify their original author as confirmer and have a confirmation timestamp. Fact source/data origin are structurally validated. This is not a new source-truth, de-identification or extraction-decision audit service.
- `chronology`: accepted correction entry cannot precede its parent's entry; extraction confirmation cannot follow accepted insertion. These reflect existing serialized insertion contracts. Equal instants are allowed. Observation time is independent: retrospective/future observations and changed observation times on correction are not rejected. No clock tolerance is invented; clock-regression anomalies remain structural findings, not clinical judgments.
- `comparison`: only distinct current roots sharing exact fact kind/key and observation instant are attempted. Key is laboratory/diagnosis/symptom code, exact medication name or history category. An exact typed payload, same author/category, same entry method and identical provenance with a nonempty reference produces POSSIBLE_DUPLICATE, never an automatic merge. Decimal equality and aware timestamp equality normalize numeric spelling/timezone offsets. Different units produce NOT_COMPARABLE/DIFFERENT_UNITS_NO_CONVERSION; other ambiguous same-time matches produce NOT_COMPARABLE/EVENT_IDENTITY_NOT_ESTABLISHED. Different-time or different-key observations receive no comparison finding. Free-text normalization, unit conversion, clinical tolerances and event identity inference are absent. Reusing a reference alone proves nothing. Any structural integrity finding skips comparison.

## Service/transaction ownership

`check_patient_consistency(db, account_id, patient_id)` requires a clean session, disables autoflush, reuses current eligibility/consent checks and the patient-level revocation gate, reads accepted current/history in that transaction and rechecks authorization before returning. It does not flush, commit, modify facts or change confirmation decisions. Malformed input errors are sanitized.

As with existing accepted-fact reads, the caller retains transaction/locks through authorized consumption and owns rollback/commit cleanup. A future API must use the existing non-streaming release gate. Returning this object after dropping locks without reauthorization is unsafe. No lock is held across external calls because none are made. Already delivered data cannot be retracted; results are not permission caches. Coarse locks, unbounded history and pairwise comparison are local-research scaling limitations.

No clinical contradiction or same-event policy has been inferred. Explicit event IDs, medication effective intervals, terminology equivalence, clock assurance, broader comparisons, durable verification/audit records and clinical gate mapping remain future decisions. No finding does not establish clinical correctness or complete runtime verification.
